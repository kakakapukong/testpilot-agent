# TestPilot 设计

## 目标

实现一个面向小型 Python 仓库的、带独立验证门的单 Coding Agent。用户提供工作目录、自然语言任务和固定的受限 pytest 验证命令；Agent 自主浏览、搜索、修改与运行命令，只有宿主在最后一次源码修改后重新执行固定验证命令且退出码为 0，任务才算成功。

## 合规边界

- 只使用普通模型 API 客户端和模型原生 function/tool calling。
- 对话历史、工具 Schema、本地工具执行、模型输出解析、循环、终止和错误处理均在仓库内实现。
- 不依赖 Agent 框架、现成 Coding Agent、MCP、托管文件工具或托管代码执行。
- 不做多 Agent、长期记忆、插件系统、并行工具、流式输出、Web UI 或复杂上下文摘要。

## 架构

1. `ModelClient` 抽象只负责把消息和工具 Schema 发给模型，并返回规范化的 `AssistantTurn`。
2. `AgentRunner` 持有消息历史与 `RunState`，串行执行 `模型 -> 工具 -> 结果回填` 循环。
3. `ToolRegistry` 静态注册七个本地工具：`list_files`、`read_file`、`search_text`、`edit_file`、`write_file`、`run_command`、`finish`。
4. `Workspace` 将所有路径约束在指定根目录；写入采用临时文件替换，精确编辑要求旧文本唯一匹配。
5. `CommandRunner` 使用参数数组和 `shell=False`；模型工具与最终验证只接受受限 pytest 命令和 workspace 内目标，并提供超时、stdout/stderr 分离和输出截断。
6. `Verifier` 保存由用户传入、模型不可修改的 pytest 验证命令，并保护默认及显式测试目标。`finish` 只表示申请结束；验证失败会作为 tool result 回填并继续循环。
7. `JsonlTrace` 记录轮次、工具名、参数摘要、耗时、退出码、验证结果和停止原因，但不记录 API key。

## 状态与终止

`RunState` 包含阶段、轮数、编辑次数、修改文件、最近验证退出码、验证是否晚于最后一次编辑、连续无进展次数和停止原因。

成功必须同时满足：模型显式调用 `finish`；至少有一次 `.py`/`.pyi` 源码修改；固定验证命令在最后一次修改之后执行；验证退出码为 0。失败出口包括模型无工具即停止、达到最大轮数、重复调用无进展、不可恢复的模型错误和验证持续失败至预算耗尽。

## 错误与安全

未知工具、坏 JSON、参数缺失、路径越界、文件不存在、非唯一编辑、命令不在允许列表、非零退出码和超时都转成结构化 `ToolResult`，不得让主循环崩溃。文件输出和命令输出均有上限。

## 测试

- 工具单测覆盖路径穿越、唯一编辑、原子写、搜索限制、命令允许列表、超时和截断。
- FakeModel 确定性测试覆盖工具调用回填、失败恢复、`finish` 验证门、最大轮数和无工具停止。
- 临时 buggy repo 端到端测试覆盖“失败测试 -> 修改源码 -> 固定验证通过”。
- API 适配器使用假 SDK 对象测试，不需要真实 key 或网络。
