# 两分钟录屏脚本

建议录屏时不要展示任何真实 API Key。离线演示可以确定性证明“修改后中断 -> 磁盘检查点 -> 新运行器恢复 -> pytest -> 只读 Reviewer -> 明确标注的模拟批准 -> 写入经验 -> 新任务检索复用”；若要证明真实人工审批，请另外在可丢弃的合成仓库中录制真实 CLI，且在开始录屏前设置好环境变量。

- `0:00–0:12`：展示仓库首页和分步 Git 提交，说明这是不用 Agent 框架、面向小型 Python 项目的测试驱动修复三 Agent。
- `0:12–0:28`：快速展示 `src/testpilot/agent.py`、`src/testpilot/reviewer.py`、`src/testpilot/memory_agent.py` 和 `src/testpilot/memory.py`。口头说明 Repair 能写，Reviewer 只读，Memory 只能提交结构化经验，宿主掌握验证、审批和持久化证据。
- `0:28–1:03`：运行 `python -m testpilot.demo`。解释第一次失败、中断恢复、pytest、Review 和模拟批准；重点展示 `MEMORY_FIRST_SAVED=yes`、`MEMORY_SECOND_RETRIEVED=1`、`MEMORY_REUSED=yes`，说明第二个任务是全新运行，不是断点恢复。
- `1:03–1:23`：只展示 `.testpilot/memories/entries.jsonl` 存在且只有 1 行，以及两份 trace 中 `memory_retrieval` / `memory_saved` 的数量、状态和错误码；不要打开记忆正文或完整 trace。
- `1:23–1:42`：在准备好的合成仓库展示真实 `APPROVAL_REQUIRED` 安全摘要；输入 `y`，展示 `review=passed`、`approval=approved`、`memory_saved=yes|duplicate` 和 `resume_available=no`。
- `1:42–1:55`：运行 focused tests，展示恢复不会重新检索、Reviewer 看不到历史记忆，以及拒绝时不写记忆并回滚原始字节。
- `1:55–2:00`：展示 full pytest 通过并总结“Repair 负责改、pytest 负责验、Reviewer 负责独立查漏、用户负责接受、Memory 负责沉淀经验”。

## 审批演示准备

1. 使用不含隐私的最小 Python 合成仓库，准备两个内容完全相同的副本，并提前记录待修复文件的哈希。
2. 批准路径：运行真实 CLI，等固定 pytest 通过和摘要出现后输入 `y`；确认最终 `approval=approved`，并确认文件哈希发生预期变化。
3. 拒绝路径：在第二个原始副本运行同一任务，摘要出现后输入 `n`；确认最终 `approval=rejected`，退出状态为失败，且文件字节或哈希与运行前完全一致。
4. 画面只展示摘要、状态和合成文件的哈希；不要展示真实源码、diff、API Key、Base URL 凭据或完整 JSONL 内容。
5. Reviewer 退回路径优先录制确定性自动化测试；真实模型是否退回具有不确定性，不要为了录屏伪造终端输出。
6. 离线 demo 中的 `APPROVED=SIMULATED` 必须按字面解释为模拟批准，不能声称已现场演示真实人工批准或拒绝回滚。

## 长期记忆演示准备

1. 用 `python -m testpilot.demo --keep .\demo-workspace` 留下合成仓库；终端应显示第一次 `memory_saved=yes`，第二次 `memories_retrieved=1`。
2. 只展示 `.testpilot/memories/entries.jsonl` 的存在性、文件大小或行数，不打开内容；JSONL 可能包含任务经验与文件名。
3. 说明记忆只在 pytest、Reviewer、人工审批三道门都通过后写入；拒绝、验证失败或 Review 失败都不会生成成功记忆。
4. 说明第二个任务是 fresh run；断点恢复沿用检查点上下文，不会在中途重新检索造成提示漂移。
5. 展示 CLI 的 `memories_retrieved`、`memory_saved`、`memory_warning`，不要展示 Memory Agent 原文、记忆 ID 或完整 trace。
6. 确认 `.testpilot/` 仍被 Git 忽略，公开仓库、最终 ZIP 和录屏画面都不包含记忆正文。

## 断点恢复演示准备

1. 首次运行时录到安全输出的 `run_id`、相对检查点路径，以及中断结果中的 `resume_available=yes`。
2. 恢复命令只传 `--workspace` 和 `--resume <run_id>`，以证明任务、verifier 和 trace 沿用原运行；可以额外用 `--max-iterations` 展示它只改变本次调用预算。
3. 恢复前后终端显示同一个 `run_id`，JSONL 中的 checkpoint 事件也应只有这一个 ID；不要打开或展示检查点正文。
4. 恢复成功后展示重新运行 pytest、全新 Reviewer 通过和人工审批，不能把中断前的验证或审查结果当作恢复后的成功证据。
5. 终态显示 `resume_available=no`，并确认 `.testpilot/checkpoints/<run_id>.json` 已删除。
6. 另用自动化测试展示文件指纹不一致会在模型使用前停止；不要为了制造效果手改真实项目。

# 正式提交前清单

1. 提供 Git 的 `user.name` 和 `user.email`，按开发过程分多次提交，不能 squash。
2. 创建公开仓库并把真实 URL 填入 `README.txt.template`，另存为 `README.txt`。
3. 录制不超过 2 分钟、大小不超过 200 MB 的 MP4；检查画面中没有 API Key、邮箱口令或其他隐私。
4. 用本人真实姓名命名 ZIP；ZIP 内只能放最终 `README.txt` 和 MP4。
5. 提交前从公开仓库重新克隆一次，按 README 命令验证离线演示能运行。
6. 若录屏包含审批，复核批准与拒绝来自两个相同的原始副本，并确认拒绝后的文件哈希确实恢复；不要只展示终端文案。
7. 复核公开仓库中能看到设计、计划、检查点格式、回滚日志、Runner 接入、CLI 恢复、离线演示和文档的分步提交；不要 squash。
8. 复核测试覆盖：Reviewer 无写工具、第一次退回最多返工一次、修改后重新 pytest、第二次退回停止、Reviewer 通过后才进入人工审批。
9. 复核恢复测试覆盖：上下文/累计轮数/重复调用保护、跨重启回滚、文件指纹拒绝、旧验证与审批失效、终态清理，以及同一 `run_id` 的 trace 连续性。
10. 确认 `.testpilot/` 仍在 `.gitignore` 中，公开仓库和提交 ZIP 都不包含本地检查点、记忆库或 trace。
11. 复核长期记忆测试覆盖：只在三道成功门后写入、最多检索 3 条、Reviewer 隔离、恢复不重复检索、凭据清理、去重、容量限制、原子写入和失败不推翻已成功修复。
