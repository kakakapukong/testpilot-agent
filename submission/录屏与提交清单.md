# 两分钟录屏脚本

建议录屏时不要展示任何真实 API Key。离线演示可以证明 Repair Agent、固定 pytest 和只读 Reviewer Agent 的顺序闭环，但它刻意不接人工审批；若要证明一次性审批，请另外在可丢弃的合成仓库中录制真实 CLI，且在开始录屏前设置好环境变量。

- `0:00–0:12`：展示仓库首页，说明这是不用 Agent 框架、面向小型 Python 项目的测试驱动修复双 Agent。
- `0:12–0:30`：快速展示 `src/testpilot/reviewer.py` 和 CLI 组装代码。口头说明 Repair Agent 有七个工具，Reviewer 只有“列/读/搜/提交结论”四个工具；两个角色使用独立上下文和模型客户端。
- `0:30–0:55`：运行 `python -m testpilot.demo`。解释 `BEFORE=FAIL` 是原始测试失败，`AGENT=SUCCESS` 是 Repair 完成修复，`REVIEW=PASS` 是第二个只读 Agent 审查通过，`AFTER=PASS` 是宿主再次运行真实 pytest 后通过；明确它不证明终端审批。
- `0:55–1:18`：在准备好的合成仓库运行真实 CLI。固定 pytest 和 Reviewer 通过后，只展示 `APPROVAL_REQUIRED`、验证退出码和 `M/A (+/-)` 摘要；输入 `y`，展示 `review=passed`、`approval=approved`，并确认修复文件被保留。
- `1:18–1:39`：运行确定性的 focused tests，展示“Reviewer 第一次退回 -> Repair 新编辑 -> 再次 pytest -> 最终 Review”，以及“第二次仍退回 -> `review_changes_remaining`、不进入审批”两个用例。不要依赖真实模型临场随机产生退回。
- `1:39–1:54`：展示 JSONL 中不含正文的 `review start/complete` 元数据，再运行 full pytest；不要展示完整源码、Reviewer 反馈或敏感配置，也不要把“测试通过”描述成 OS 沙箱证明。
- `1:54–2:00`：总结“Repair 负责改、pytest 负责确定性验证、Reviewer 负责只读查漏、用户负责最终接受”。

## 审批演示准备

1. 使用不含隐私的最小 Python 合成仓库，准备两个内容完全相同的副本，并提前记录待修复文件的哈希。
2. 批准路径：运行真实 CLI，等固定 pytest 通过和摘要出现后输入 `y`；确认最终 `approval=approved`，并确认文件哈希发生预期变化。
3. 拒绝路径：在第二个原始副本运行同一任务，摘要出现后输入 `n`；确认最终 `approval=rejected`，退出状态为失败，且文件字节或哈希与运行前完全一致。
4. 画面只展示摘要、状态和合成文件的哈希；不要展示真实源码、diff、API Key、Base URL 凭据或完整 JSONL 内容。
5. Reviewer 退回路径优先录制确定性自动化测试；真实模型是否退回具有不确定性，不要为了录屏伪造终端输出。
6. 如只录离线 demo，必须明确它证明的是非交互双 Agent/pytest 闭环，不能声称已现场演示人工批准或拒绝回滚。

# 正式提交前清单

1. 提供 Git 的 `user.name` 和 `user.email`，按开发过程分多次提交，不能 squash。
2. 创建公开仓库并把真实 URL 填入 `README.txt.template`，另存为 `README.txt`。
3. 录制不超过 2 分钟、大小不超过 200 MB 的 MP4；检查画面中没有 API Key、邮箱口令或其他隐私。
4. 用本人真实姓名命名 ZIP；ZIP 内只能放最终 `README.txt` 和 MP4。
5. 提交前从公开仓库重新克隆一次，按 README 命令验证离线演示能运行。
6. 若录屏包含审批，复核批准与拒绝来自两个相同的原始副本，并确认拒绝后的文件哈希确实恢复；不要只展示终端文案。
7. 复核公开仓库中能看到设计、计划、Reviewer 实现、编排实现、CLI 接入和文档的分步提交；不要 squash。
8. 复核测试覆盖：Reviewer 无写工具、第一次退回最多返工一次、修改后重新 pytest、第二次退回停止、Reviewer 通过后才进入人工审批。
