# 两分钟录屏脚本

建议录屏时不要展示任何真实 API Key。离线演示可以证明 Agent 闭环真实执行了 pytest，但它刻意不接人工审批；若要证明一次性审批，请另外在可丢弃的合成仓库中录制真实 CLI，且在开始录屏前设置好环境变量。

- `0:00–0:12`：展示仓库首页，说明这是不用 Agent 框架、面向小型 Python 项目的测试驱动修复单 Agent。
- `0:12–0:28`：快速展示 `src/testpilot/`，口头说明七个工具、模型循环、固定验证门、一次性人工决定和 JSONL 轨迹均为本地实现。
- `0:28–0:55`：运行 `python -m testpilot.demo`。解释 `BEFORE=FAIL` 是原始测试失败，`AGENT=SUCCESS` 是非交互 demo 完成修改和验证，`AFTER=PASS` 是宿主再次运行真实 pytest 后通过；明确它不证明终端审批。
- `0:55–1:18`：在准备好的合成仓库运行真实 CLI。固定 pytest 通过后，只展示 `APPROVAL_REQUIRED`、验证退出码和 `M/A (+/-)` 摘要；输入 `y`，展示 `approval=approved`，并确认修复文件被保留。
- `1:18–1:41`：从相同的原始合成仓库副本再次运行，输入 `n`。展示 `approval=rejected` 和失败状态，再比较运行前后的文件哈希，证明原始文件被恢复。不要用第一次已批准的目录冒充“原始状态”。
- `1:41–1:54`：运行 focused/full pytest，展示自动化测试覆盖批准、拒绝、输入不可用和回滚；不要把“测试通过”描述成 OS 沙箱证明。
- `1:54–2:00`：总结“模型只能建议工具调用；真实 CLI 成功由固定验证和一次明确人工批准共同决定”。

## 审批演示准备

1. 使用不含隐私的最小 Python 合成仓库，准备两个内容完全相同的副本，并提前记录待修复文件的哈希。
2. 批准路径：运行真实 CLI，等固定 pytest 通过和摘要出现后输入 `y`；确认最终 `approval=approved`，并确认文件哈希发生预期变化。
3. 拒绝路径：在第二个原始副本运行同一任务，摘要出现后输入 `n`；确认最终 `approval=rejected`，退出状态为失败，且文件字节或哈希与运行前完全一致。
4. 画面只展示摘要、状态和合成文件的哈希；不要展示真实源码、diff、API Key、Base URL 凭据或完整 JSONL 内容。
5. 如只录离线 demo，必须明确它证明的是非交互 Agent/pytest 闭环，不能声称已现场演示人工批准或拒绝回滚。

# 正式提交前清单

1. 提供 Git 的 `user.name` 和 `user.email`，按开发过程分多次提交，不能 squash。
2. 创建公开仓库并把真实 URL 填入 `README.txt.template`，另存为 `README.txt`。
3. 录制不超过 2 分钟、大小不超过 200 MB 的 MP4；检查画面中没有 API Key、邮箱口令或其他隐私。
4. 用本人真实姓名命名 ZIP；ZIP 内只能放最终 `README.txt` 和 MP4。
5. 提交前从公开仓库重新克隆一次，按 README 命令验证离线演示能运行。
6. 若录屏包含审批，复核批准与拒绝来自两个相同的原始副本，并确认拒绝后的文件哈希确实恢复；不要只展示终端文案。
